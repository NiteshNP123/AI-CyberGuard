# AI CyberGuard — Full-Stack AI Cybersecurity Platform

Build a production-style full-stack web application called **AI CyberGuard**, an AI-powered unified cybersecurity platform that combines multiple defensive security analysis modules into a single dashboard.

## 1. Project Objective

AI CyberGuard should act as a centralized cybersecurity assistant capable of analyzing different types of security threats, assigning risk scores, explaining why something is suspicious, and maintaining a history of security events.

The platform should combine:

* AI-based Network Intrusion Detection
* AI URL and Website Threat Detection
* AI Phishing/Fraud Email and Message Detection
* Wi-Fi Security Analysis
* File/Malware Static Analysis
* Login Anomaly Detection
* Account Takeover Detection
* DNS Threat Detection
* QR Code Security Analysis
* Data Leak / Sensitive Information Detection
* Unified AI Threat Correlation and Risk Engine

The project must be designed as a **real full-stack application**, not just a frontend connected directly to an AI API.

---

# 2. Technology Stack

## Frontend

Use:

* React
* JavaScript/TypeScript
* Tailwind CSS
* Recharts or another suitable charting library

Create a modern cybersecurity dashboard with responsive design, cards, charts, tables, alerts, filters, and detailed analysis pages.

## Backend

Use:

* Python
* FastAPI
* REST APIs
* JWT-based authentication

The backend should contain separate services/modules for each security analyzer.

## Database

Use:

* PostgreSQL

Store:

* Users
* Projects
* Scan history
* URLs analyzed
* Message analyses
* Network events
* Threat detections
* Risk scores
* Alerts
* Reports
* Model results

Use Redis optionally for caching and background jobs.

## AI/ML

Use Python-based ML components such as:

* Scikit-learn
* XGBoost
* PyTorch where necessary
* NLP models
* LLM API for explanations and advanced reasoning

Do not make the entire project dependent on an LLM. Use traditional ML/statistical techniques where appropriate.

# 5. AI Network Intrusion Detection System

Create an AI-based network intrusion detection module.

The system should analyze network-flow data and detect:

* Normal traffic
* DoS/DDoS patterns
* Port scanning
* Brute-force activity
* Botnet-like behavior
* Abnormal traffic
* Other suspicious network behavior

Use network-flow features such as:

* Source IP
* Destination IP
* Source port
* Destination port
* Protocol
* Flow duration
* Packet count
* Byte count
* Packet rate
* TCP flags

Support dataset-based analysis initially.

Structure the system so real-time network telemetry can be integrated later through tools such as Zeek or Suricata.

Display:

* Attack type
* Confidence
* Risk score
* Source/destination information
* Timestamp
* Explanation
* Severity

# 6. AI URL and Website Security Analyzer

Create a URL analysis page.

Allow the user to enter a URL.

Analyze safe, defensive indicators such as:

* URL structure
* Domain characteristics
* HTTPS/TLS
* Redirect behavior
* Suspicious patterns
* Threat-intelligence results
* Domain reputation where legitimate APIs are available
* Possible phishing indicators

Return:

* Safe / Suspicious / Malicious / Unknown
* Risk score from 0–100
* Confidence
* Detected indicators
* Explanation
* Recommended action

Do not automatically perform dangerous actions against websites.

# 7. Browser Extension

Design the architecture so AI CyberGuard can later support a browser extension.

The extension should:

* Detect the current page URL
* Send the URL to the backend
* Receive the security assessment
* Display a simple indicator:

Green = Low Risk
Yellow = Suspicious
Red = High Risk

Clicking the extension should show a detailed explanation.

Do not block websites automatically unless the user explicitly enables such functionality.

# 17. AI Risk Engine

Create a central risk-scoring system.

Each module should produce:

* Detection
* Confidence
* Severity
* Evidence

The risk engine combines these signals and calculates an overall risk score.

Example:

0–30 = Low
31–60 = Medium
61–80 = High
81–100 = Critical

Make the scoring system transparent and explainable.

# 27. Important Safety Requirements

This is a defensive cybersecurity project.

Only analyze:

* User-provided content
* Authorized networks
* Authorized systems
* Controlled datasets
* Sandboxed files

Do not implement features designed to:

* Attack external systems
* Steal credentials
* Bypass authentication
* Crack Wi-Fi passwords
* Perform unauthorized scanning
* Execute uploaded malware on the host system

Use sandboxing and strict resource limits for any code or file execution.

# 29. Final Goal

The finished application should demonstrate:

**Full-Stack Development**
React + FastAPI + PostgreSQL

**AI/ML**
Classification + anomaly detection + NLP + explainability

**Cybersecurity**
IDS + phishing detection + network analysis + threat intelligence

**Software Engineering**
REST APIs + authentication + database design + modular architecture

**Advanced AI**
Threat correlation + AI reasoning + unified risk scoring

The final system should feel like a **unified AI-powered Security Operations Center (SOC) assistant for individual users or small organizations**, rather than a collection of unrelated scanners.

Build the project in a modular way so every security module can be developed, tested, and deployed independently while still contributing events to the central AI Threat Correlation and Risk Engine.
